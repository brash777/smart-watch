# Snapia conventions

Apply these conventions every time you create or edit a file in this repository. If a request seems to conflict with them, stop and ask before going ahead.

## 1. Know the product

Snapia is an AI instant-photo app built for the Smart Wash project: "Take the photo. The AI does the rest."
People take quick photos (snaps), Instagram-style, and save them in Spaces.
Each Space has a mode (STUDY, WORK or CONTENT) that decides what the AI does with its snaps.
STUDY gives notes, summaries, flashcards, quizzes and assignment guides; WORK gives reports with photo evidence; CONTENT gives captions, posts and a portfolio.
A social layer sits on top: Moments, Posts, follows, likes, comments and shared Spaces.

Read [`docs/PRODUCT.md`](../../../docs/PRODUCT.md) before you start. **Its glossary is mandatory:**

- Use the glossary names exactly as written in models, types, files, routes and components: `User`, `Space`, `SpaceMember`, `SpaceInvite`, `Snap`, `SnapInsight`, `Document`, `FlashcardDeck`, `Quiz`, `AskMessage`, `Moment`, `Post`, `AiRun`, `AppSetting`.
- Use the enum values exactly as written: `STUDY`, `WORK`, `CONTENT`; `PRIVATE`, `MEMBERS`, `PUBLIC`; `OWNER`, `EDITOR`, `VIEWER`; `USER`, `ADMIN`; and the Document types (`STUDY_NOTES`, `WORK_DAILY_REPORT`, …).
- No synonyms in code: a Space is not a `folder`, `album` or `board`; a Moment is not a `story`; a Snap is not a `photo` or `image` entity. Only the Spanish UI text translates them ("Espacio", "Instante").
- If you need a concept the glossary does not have, ask first, then add it to the glossary in the same change.

## 2. Folder structure

```text
.
├── apps/
│   ├── api/
│   │   ├── prisma/
│   │   │   ├── schema.prisma          # data model
│   │   │   ├── migrations/            # generated by Prisma, committed, never edited after commit
│   │   │   ├── seed.ts                # idempotent seed logic, no data inside
│   │   │   └── seed-data/*.json       # seed data (AppSetting values, …)
│   │   └── src/
│   │       ├── config/                # env loading + Zod validation; the only place that reads process.env
│   │       ├── modules/<feature>/     # routes, controller, service, repository, schemas, tests
│   │       ├── middlewares/           # authenticate, requireRole, requireSpaceRole, validate, error handler
│   │       ├── lib/                   # shared infrastructure: Prisma client, storage, logger, AppError, …
│   │       └── types/                 # backend-only types (e.g. Express request augmentation)
│   └── web/
│       └── src/
│           ├── app/                   # app shell: providers, router, layouts
│           ├── features/<feature>/    # pages/, components/, hooks/, api.ts
│           ├── components/            # UI reused by several features
│           ├── lib/                   # http client, query client, i18n setup, helpers
│           └── i18n/locales/          # es.json: every user-facing string
├── packages/
│   └── shared/
│       └── src/
│           ├── schemas/               # Zod schemas used by api and web (inputs, outputs, AI outputs, enums)
│           └── types/                 # TypeScript types inferred from those schemas
└── docs/                              # PRODUCT.md, api.md
```

Where new code goes:

| You are adding… | Put it in… | Skill |
| --- | --- | --- |
| An API endpoint or backend feature | `apps/api/src/modules/<feature>/` | `api-module` |
| An AI task or prompt | `apps/api/src/modules/ai/` | `ai-vision-task` |
| A table, column, relation or seed data | `apps/api/prisma/` | `prisma-change` |
| A screen or component | `apps/web/src/features/<feature>/` (or `apps/web/src/components/` if reused) | `react-feature` |
| A schema or type used by both api and web | `packages/shared/src/` | — |
| A commit, push or pull request | — | `git-commit` |

Never duplicate a schema or a type in `apps/api` and `apps/web`: define it once in `packages/shared` and import it from both.

## 3. Naming

| What | Convention | Example |
| --- | --- | --- |
| Files and folders | kebab-case | `space-invite.service.ts`, `snap-card.tsx`, `seed-data/` |
| React components | PascalCase (the file is still kebab-case) | `snap-card.tsx` exports `SnapCard` |
| Variables, functions, hooks | camelCase | `takenAt`, `createSpace`, `useSpaceSnaps` |
| Types, interfaces, classes | PascalCase | `AppError`, `CreateSpaceInput` |
| Zod schemas | camelCase ending in `Schema` | `createSpaceSchema` |
| Environment variables | UPPER_SNAKE_CASE | `DATABASE_URL`, `AI_PROVIDER` |
| Enum values and error codes | UPPER_SNAKE_CASE | `WORK_DAILY_REPORT`, `SPACE_NOT_FOUND` |
| Prisma models | PascalCase, singular, from the glossary | `SpaceMember` |
| Database tables | snake_case, plural, with `@@map` | `@@map("space_members")` |
| Database columns | snake_case with `@map` | `takenAt DateTime @map("taken_at")` |
| i18n keys | dot-separated, grouped by feature, camelCase segments | `spaces.createForm.nameLabel` |

## 4. Language

- **English** for everything technical: code, identifiers, file names, comments, commit messages and technical docs (`docs/`, `README.md`, skills).
- **Spanish** for everything the user sees, and only in `apps/web/src/i18n/locales/es.json`, read with `t('key')`. That includes button labels, placeholders, `alt` texts, `aria-label`s, toasts, empty states and error messages.
- API error messages are English and meant for developers. The web app shows the Spanish text for the error `code` (`t('errors.<CODE>')`).

## 5. No hardcoded values

Never write URLs, ports, credentials, keys, the app name, AI model names, limits, thresholds or durations in code. Not as defaults and not "for now".

| Value | Where it lives | How code reads it |
| --- | --- | --- |
| Secrets, credentials, API keys, URLs, ports | `.env` (documented in `.env.example`), validated with Zod in `apps/api/src/config` | the typed `config` object |
| App name, AI provider and model, AI limits (tokens, timeout, retries, image size, context size), pagination limits | `.env` + Zod config | `config` |
| Web app settings (API base URL, …) | `VITE_*` variables of `apps/web` | `import.meta.env.VITE_*`, read in one typed module |
| Product rules (Moment duration, invite defaults, AI output language, AI token prices, …) | `AppSetting` table, seeded from `apps/api/prisma/seed-data/*.json` | the settings service |
| User-facing text | `apps/web/src/i18n/locales/es.json` | `t('key')` |
| AI prompts | versioned files in `apps/api/src/modules/ai/prompts/` | the prompt loader (`{{placeholders}}`) |
| Colors, spacing, radii | CSS variables + `tailwind.config` | token classes |

**Rule of thumb:** if an admin should be able to change it without a deploy, it is an AppSetting; if it depends on the environment or it is a secret, it is an environment variable; if the user reads it, it goes in `es.json`.

Not hardcoded values: glossary enum values (`STUDY`), HTTP status codes, i18n keys, token class names and test fixtures.

Every time you add an environment variable:

1. Add it to the Zod schema in `apps/api/src/config` (or to the typed env module of `apps/web`). Do not give URLs, ports or secrets a default in code.
2. Add it to `.env.example` with a safe placeholder and a one-line comment.
3. Read it only through `config` (`process.env` never appears outside the config module).

## 6. Checklist before you finish

- [ ] No user-facing strings in components: every visible text uses `t('…')` and its key exists in `es.json`.
- [ ] No URLs, ports, credentials, app name, model names, limits, thresholds or durations in code.
- [ ] `.env.example` lists every environment variable the code reads.
- [ ] Schemas and types used by both apps live in `packages/shared`, with no copies.
- [ ] Every route that touches a Space checks membership and role (`requireSpaceRole`).
- [ ] Glossary names and enum values used exactly; code and comments in English.
- [ ] Naming conventions followed.
- [ ] Tests added or updated; lint, typecheck and tests pass.

Quick searches that catch common slips (review each hit, not every hit is a bug):

```bash
# URLs and hosts written in source code
grep -rnE "https?://|localhost" apps/*/src packages/*/src --include='*.ts' --include='*.tsx'
# AI model names written in source code
grep -rnE "claude-[a-z]" apps/*/src packages/*/src --include='*.ts' --include='*.tsx'
# environment access outside the config module
grep -rn "process\.env" apps/api/src --include='*.ts' | grep -v '/config/'
```
